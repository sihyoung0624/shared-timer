# 모두의 타이머 (Shared Timer)

여러 명이 각자 노트북·폰으로 **동일한 카운트다운을 실시간으로** 보는 웹 타이머입니다.
진행자(컨트롤러)가 시간을 제어하고, 참석자(뷰어)는 큰 화면으로 남은 시간을 봅니다.
발표·회의·수업·면접, 온라인 게임 공격대(레이드) 지휘 등에 사용합니다.

- **서비스:** https://shared-timer-d07t.onrender.com
- **저장소(비공개):** https://github.com/sihyoung0624/shared-timer
- **호스팅:** Render (무료 플랜) — `main` 브랜치에 **푸시하면 자동 재배포**
- ⚠️ 무료 플랜은 **15분간 미사용 시 잠들어**, 첫 접속이 **~50초** 걸립니다.
  사용 5분 전에 주소를 한 번 열어 깨워두면 바로 쓸 수 있습니다. (항상 켜두려면 유료 플랜)

## ✨ 주요 기능

- **실시간 공유 카운트다운** — 모든 기기가 같은 시간을 봄 (WebSocket 동기화)
- **뷰어 / 컨트롤러 분리** — 링크를 분리하고, 제어 토큰을 **서버에서 검증**
- **QR 코드** — 뷰어 링크 QR로 다수가 폰으로 동시 접속
- **종료 알림** — 소리(삑삑삑) + 진동(안드로이드) + 화면 깜빡임
- **즉석 메시지** — 진행자가 입력하면 전원 화면에 크게 표시 + 알림음(딩동)
- **예약 메시지** — "남은 시간 N일 때 이 메시지" 를 미리 등록 → 자동 표시
- **예약 시작** — 지정한 시각(예: 오후 3시)에 자동 시작, 그 전엔 대기 화면 + 시작까지 카운트다운
- **실시간 투표(선택형)** — 질문+선택지 2~4개. 뷰어가 폰으로 선택, 진행자는 실시간 막대그래프.
  결과는 기본 비공개, 진행자가 **결과 공개 토글**로 제어. 재선택 시 이전 표 대체(느슨한 1인 1표)
- **선착순 손들기** — 큰 버튼 하나, 누른 순서대로 순위(1~10등) 명단. 누른 사람에게 즉시 등수 통보
- **선착순 퀴즈** — 정답 지정. 정답자만 빠른 순으로 순위. 진행 중엔 정답·순위를 뷰어에게 숨김(컨닝 차단)
- 시간 미세조정(±), 일시정지·리셋, 전체화면, 소리 켜기
- **카드형 다크 UI** (뷰어 화면은 큰 숫자만 심플)

## 1. 로컬 실행 (개발용)

```powershell
# 1) 가상환경 생성 (Python 3.11 권장)
py -3.11 -m venv .venv

# 2) 가상환경 활성화
.\.venv\Scripts\Activate.ps1

# 3) 패키지 설치
pip install -r requirements.txt

# 4) 실행
python app.py
```

- 이 컴퓨터:           `http://localhost:5050`
- 같은 와이파이 기기:  `http://<이PC의IP>:5050`  (콘솔에 자동 표시됨)

> 기본 포트는 **5050**입니다(개발 PC에서 5000번을 다른 프로그램이 사용 중). 변경은 환경변수 `PORT`.

## 2. 사용 방법

1. 홈(`/`)에서 시간을 설정하고 **타이머 만들기** 클릭
2. **두 개의 링크 + QR**이 발급됩니다.
   - **뷰어 링크** (`/v/<room_id>`) : 시간만 봄. 청중·프로젝터용. → **QR로 공유**
   - **컨트롤러 링크** (`/c/<room_id>/<token>`) : 시작·정지·메시지·예약 등 제어. **진행자 본인만**
3. 진행자는 컨트롤러로 제어하고, 참석자에게는 **뷰어 링크(또는 QR)만** 공유합니다.

> ⚠️ 컨트롤러 화면을 프로젝터에 직접 띄우면 주소창에 토큰이 노출됩니다.
> **공유·발표 화면은 반드시 뷰어 링크로** 띄우세요.

**투표·선착순 사용 흐름 (컨트롤러의 "실시간 투표·선착순" 카드):**
1. 모드 선택 — `선택 투표` / `선착순 손들기` / `선착순 퀴즈`
2. 질문(+ 선택지, 퀴즈는 정답까지) 입력 → 시작 → 뷰어 화면에 알림음과 함께 등장
3. 진행자는 실시간 집계(막대그래프)·순위 명단을 보고, **결과 공개** 토글로 뷰어 공개 여부 제어
4. **종료** → 결과 고정 → **새로 만들기**로 반복
- 선착순 참여자는 첫 참여 시 닉네임(순위표 표시용)을 입력합니다(기기에 저장, 1회만).

## 3. 인터넷 배포 (Render)

자세한 단계는 **[DEPLOY.md](DEPLOY.md)** 참고. 요점만:

- **Build Command:** `pip install -r requirements.txt`
- **Start Command:** `gunicorn -k eventlet -w 1 --bind 0.0.0.0:$PORT app:app`
  - `--bind 0.0.0.0:$PORT` 필수 (없으면 Render가 포트를 못 찾아 timeout)
- **환경변수:** `SECRET_KEY`(운영용 랜덤값) — 그 외 `CORS_ORIGINS`, `PUBLIC_BASE_URL` 등은 선택
- **Python 버전:** `.python-version` 파일로 3.11.9 자동 지정
- **버전 고정 주의:** `gunicorn`·`eventlet`은 서로 호환되는 버전으로 고정해야 함
  (`requirements.txt`에 `gunicorn==21.2.0`, `eventlet==0.33.3` 고정 — 최신끼리는 worker 충돌 사례 있음)

## 5. 보안 설계 (반영된 원칙)

| 원칙 | 구현 |
|------|------|
| 뷰어 / 컨트롤러 권한 분리 | 링크(URL) 분리. 뷰어는 토큰 없음 |
| 컨트롤러 토큰 **서버 검증** | `_check_controller()` — 클라이언트 값을 서버 보관값과 대조 |
| 외부 데이터에 토큰 미포함 | `_snapshot()`·`_poll_public()` 이 민감정보를 항상 제외 |
| **XSS 차단** | 메시지·예약·투표 질문·닉네임을 화면에 넣을 때 `textContent`만 사용 |
| 동시 사용 보호 | `rooms_lock`(threading.Lock)으로 방 데이터 보호 |
| 입력 검증 | 시간 범위·타입 체크·접속 상한 + 투표(없는 선택지·종료된 투표·선택지 2~4개·퀴즈 정답 필수) |
| 비밀키·CORS 환경변수 | `SECRET_KEY`, `CORS_ORIGINS`를 환경변수로 주입 |
| 남용 방지 | 방 개수 상한(`MAX_ROOMS`) + 오래된 방 자동 정리(`ROOM_TTL`) |
| **투표 데이터 격리** | 방(room) 단위 완전 격리. 집계·순위는 컨트롤러 전용 채널(`room:ctrl`)로만 전송 |
| **컨닝 차단(퀴즈)** | 정답·순위·정답 여부를 '결과 공개' 전까지 뷰어에게 절대 미전송 |
| **순위 조작 방지(선착순)** | 누른 시각을 서버 시계로 기록(클라이언트 시계 무관), 첫 클릭이 최종(재클릭 무시) |

## 6. 운영·확장 시 남은 고려사항

- **단일 서버·메모리 저장** — 서버를 2대 이상으로 늘리면 방 데이터가 공유되지 않음.
  대규모(수백~수천 동시)로 키우려면 **Redis** 등 외부 저장소 + Socket.IO 메시지 큐 필요.
- **영속성 없음** — 서버 재시작 시 진행 중이던 타이머 소멸. 기록이 필요하면 DB 연동.
- **남용 방지 강화 여지** — 현재는 방 개수 상한·자동 정리 수준. 공개 규모가 커지면 IP별 생성 제한(rate limit) 등 추가 권장.
- **무료 플랜 슬립** — 위 "배포된 주소" 참고. 상시 가동이 필요하면 유료 플랜.
- **투표는 "느슨한 1인 1표"** — 브라우저(localStorage) 기준이라 시크릿창·다른 브라우저로 중복 참여 가능.
  재미·현장용 전제. 상품·심사 등 공정성이 중요한 용도는 **로그인 기반 1인 1표**로 확장 필요
  (각 표에 서버시각 `ts`가 이미 기록되므로 확장 용이).
- **선착순 공정성 한계** — 참가자 네트워크 속도의 영향을 받음(모든 온라인 선착순 공통). 엄격한 경쟁용은 지연 보정 검토.

- **Python 3.11.9** 에서 개발·검증 (`.python-version`으로 배포에도 동일 적용).
